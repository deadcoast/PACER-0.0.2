# PACER AGENT START

Read in this order:

1. `.MIVIM.spec`
2. `PREPROMPT.txt`
3. `todo.PACER`
4. `rules.overlord.rs`
5. only the source anchors needed by the active phase

Then work.

## Default behavior

Do **not** stop after one pace because a check exists.

A PACER pace normally ends by updating state and continuing through `:loop⠁:`. The agent owns research, implementation, local validation, repair, integration, and documentation within the authorized project scope.

Ask the user only when the next action requires authority the package cannot supply: an irreversible external action, a destructive decision affecting protected/released material, a missing secret/account, or a genuinely mutually exclusive product direction with major downstream cost and no existing project answer.

Ordinary test failures, implementation uncertainty, greybox tuning, local architectural choices, formatting, linting, or lack of user playtesting are **not** authority blockers at prototype/integration maturity.

## Context discipline

Use PACER as a context router:

- **WELL** = global project knowledge, source anchors, decisions, prior phases.
- **THEATRE** = the small actionable slice required for the current phase.

Do not reload the entire WELL for every pace. Keep the global map and current phase alive; pull deeper sources only when the current work needs them.
