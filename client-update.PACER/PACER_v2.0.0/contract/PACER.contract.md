# PACER v2 Behavioral Contract

## Required

1. Keep the global project map available while operating on a bounded active phase.
2. Integrate related paces into one source system before declaring the phase coherent.
3. Treat tests/research/docs as agent-side work unless they expose a real authority blocker.
4. Execute `:loop⠁:` before OVERLORD state update and continue automatically when an eligible pace remains.
5. Persist approvals/skips as latches; do not repeatedly request the same authorization.
6. Increase gate strictness with project maturity.
7. Preserve source authority and explicit user direction over PACER inference.

## Forbidden defaults

- one user checkpoint per pace;
- mandatory REVIEW state after ordinary implementation;
- stopping because a simple test was not manually run by the user;
- dropping the global/future plan while blocked on a small local issue;
- duplicating the same project context into dozens of detached task documents;
- treating validation artifacts as the development product;
- using PACER to manufacture process when the project already supplies the answer.

## Compatible legacy concepts

`:nodule`, `+approved`, `->:absorb::nodule`, `?if`, `NDL-*`, `OGM-*`, task checkboxes, OVERLORD maps/rules, and source anchors remain valid. Their operational meaning is subordinated to continuity-first execution.
